<h3><img src="resources/app.png" /> json_formatter</h3>TL;DR  json in,  json out.<hr/>originally designed to deep sort (including arrays) JSON files,  for a deterministic output,  that makes it easier to compare them side by side  with programs such as BeyondCompare.  <hr/>```txtUsage:  json-format [RAW_JSON5] [OPTIONS]Input precedence:  1. --input-file=PATH  2. piped stdin  3. first argument not starting with --Options:  --input-file=PATH  --output-file=PATH  --output-format=json_minified|json_beautified  --output-sort=no-sort|sort-keys|sort-keys-arrays  --output-eol=os|win|nxDefaults:  --output-format=json_beautified  --output-sort=no-sort  --output-eol=os```<hr/>reads JSON5, i.e. a loose/permissive variation of JSON looks like JavaScript's Object (optional quotes/comments),  and outputs a valid JSON.  <hr/>`json_formatter` is written with Rust,  and powered by https://docs.rs/json5/latest/json5/ for supporting JSON5 https://json5.org/  and https://docs.rs/serde_core/latest/serde_core/ for serializing the JSON objects into text.  <hr/>`json_formatter` favors `--input-file=` for input. it reads from the file the json content.  if that isn't available it tries to read the initial `STDIN`,  this is often the output of previous program's `STDOUT` in pipeline command-line.  if initial `STDIN` isn't available, for example if the program is ran from interactive terminal,  it tries to find the first argument that does not starts with `--` and tries to parse it as a json content.  if not found it will fail (with a message, and exit code that isn't `0`).  <hr/>the output is beautified by default, unless you specified minified.  the output's end-of-line characters are set to match your operation-system,  `\r\n` for Windows, and `\n` for anything else (unix, linux, osx/macos, android, ..)<hr/>### output sortingJSON object has no specific importance for having the keys of an object in a specific order,  so you can specify `--output-sort=sort-keys` to naturally deep sort (`1<2<10<20`) every object by its keys,  and still preserve the JSON meaning.  you can take things another level and use `--output-sort=sort-keys-arrays`,  which makes json_formatter also deep sort arrays.  this is mostly useful when:  - you use json to store information but not care about the order.  - want deterministic output as much as possible, that changes only when actual data is added/removed.  - you want to compare two JSON files for their content, ignoring any variations of entries-order.  sorting helps you ignore variations that your "json writer" introduced while writing.  <hr/>#### example:  input:  ```json{  outer: [    { z: 2, a: 1 },    { b: [3, 1, 2], a: "x" },    [20, 2, 10]  ]}```output with `--output-sort=no-sort````json{  "outer": [    {      "z": 2,      "a": 1    },    {      "b": [        3,        1,        2      ],      "a": "x"    },    [      20,      2,      10    ]  ]}```output with `--output-sort=sort-keys````json{  "outer": [    {      "a": 1,      "z": 2    },    {      "a": "x",      "b": [        3,        1,        2      ]    },    [      20,      2,      10    ]  ]}```output with `--output-sort=sort-keys-arrays````json{  "outer": [    [      2,      10,      20    ],    {      "a": "x",      "b": [        1,        2,        3      ]    },    {      "a": 1,      "z": 2    }  ]}```<hr/>here is how to do pretty much the same using  jq https://github.com/jqlang/jq (the command-line JSON processor).  for deep sorting, but with preserving of arrays order:```txtjq '  walk(    if type == "object" then      to_entries      | sort_by(.key)      | from_entries    else      .    end  )' input.json```for sorting arrays too:  ```txtjq '  def deep_sort:    if type == "object" then      to_entries      | map(.value |= deep_sort)      | sort_by(.key)      | from_entries    elif type == "array" then      map(deep_sort)      | sort_by(tojson)    else      .    end;  deep_sort' input.json```<hr/><br/><br/><hr/>### build:```rustup updatecargo cleanrustup target add   x86_64-pc-windows-msvc   i686-pc-windows-msvccargo build  --release  --target
